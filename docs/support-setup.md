# iOS 开发支持：配置说明

官网在下载页面展示 iOS / iPadOS 支持计划。未接入爱发电前，页面只显示暂定目标 ¥750 和“尚未同步 / 支持入口准备中”；不得使用假订单。

## 启用自动统计

1. 在爱发电创建**独立的 iOS 开发支持方案**，确认该方案的 `plan_id`，不要把账户里其他赞助或销售订单混入统计。
2. 在 `Lee7017/lingcang` 仓库 Settings → Secrets and variables → Actions 的 **Secrets** 添加：
   - `AFDIAN_USER_ID`（创作者开发者 API user_id）
   - `AFDIAN_API_TOKEN`（创作者 API Token）
   - `AFDIAN_PLAN_ID`（仅统计此 iOS 开发支持方案的订单）
3. 在 **Variables** 添加 `AFDIAN_SUPPORT_URL`（真实的爱发电 HTTPS 主页或方案链接）。未设置时，官网不会展示可点击的收款按钮。
4. 检查 GitHub Pages 的 `github-pages` 环境及 Actions 权限，手动运行 `Sync iOS support statistics` 验证；然后才依赖每五分钟的定时任务。

必须在第一次开通真实收款后验证爱发电返回的订单字段、退款后的订单状态与对账结果。在未验证退款行为前，不得声称能自动识别所有退款；必要时暂停同步并人工核对。

## 数据保护与显示规则

- Token、原始订单、订单号、私有用户 ID、订单留言、手机号和地址**绝不提交到公开 Git 仓库或 Pages 产物**。
- 公开文件 `docs/public/support/ios.json` 只有累计金额、人数、同步时间、目标、公开支持入口和经允许公开的名单。
- `supporters` 默认空数组。不得直接把 API 返回的用户昵称与个人金额公开；先取得本人明确同意，之后再开发专门的公示名单维护流程。
- 一笔成功付款只计算一次，按 `total_amount` 统计；支持人数按有效订单中的爱发电用户 ID 在本次同步时去重（用户 ID 不写入输出）。
- 后台每五分钟尝试同步一次。如果金额/人数不变，最多每小时才重新部署一次网站，减轻 GitHub Actions 和 Pages 负担。网页**只在首次进入和用户手动点击刷新时请求公开 JSON**。
- 数据查询失败时不得覆盖上次成功的数据。公开文件里的 `syncedAt` 是最近一次实际部署的数据同步时间。
- 前端尚未收集手机号，也没有账号余额、短信通知、实时支付回调。爱发电能否独立强制收集手机号待验证。

## 与官网部署的关系

原有 `deploy.yml` 保留，网站代码推送仍照常部署；定时同步工作流只有统计变化或同步时间超过一小时时才单独重新构建并部署 Pages。

如长期不更新仓库，公开仓库的 GitHub Actions schedule 可能停用，需要到 Actions 页面恢复。正式页面应始终显示真实的最近同步时间，不暗示实时性。
